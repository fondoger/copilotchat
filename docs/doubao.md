# 豆包网页版

在 Settings → Providers 中点击添加按钮，选择「豆包」。保留或修改 Provider name，并在下方网页中自行扫码登录。

在聊天顶部选择菜单的 Web Chat 分组中选择豆包，然后通过 Copilot Chat 的 New Chat 开始会话。消息输入和回复直接使用豆包网页；网页侧栏只在聊天页隐藏，Provider 设置页仍显示完整网页。

从 Copilot Chat 创建的豆包会话会保存网页链接和自动生成的标题，可以通过本地侧栏重新打开。设置页中浏览或创建的会话、账号中原有的历史不会自动导入。本地重命名会保留，不被网页自动标题覆盖；本地删除仅删除此设备中的会话记录，不删除豆包账号中的会话。

网页获得焦点后仍可使用应用的 New Chat、搜索、侧栏、模型菜单和会话切换快捷键；普通复制粘贴和输入交给网页处理。仅聊天 WebView 信任精确来源 `https://www.doubao.com`，快捷键接口校验当前页面和窗口。MyGo 的来源信任也允许该来源调用框架内置窗口操作，设置页和认证来源不授予该权限。

聊天会话复用同一个 WebView：切换时优先点击豆包网页自身的会话链接或新对话入口，在同一文档内导航，减少整页空白加载。目标历史项尚未加载到网页侧栏、入口不可用或切换超时时，回退为先完成 `about:blank` 导航，再加载保存的会话 URL；不调用豆包私有 API，也不自动翻页查找历史。切到原生会话后最多保留 5 分钟，回来时取消释放；超时会销毁 WebView、停止观察并移除事件监听。关闭应用、删除会话、删除或禁用 Provider 会立即释放对应页面。设置环境变量 `COPILOT_CHAT_WEBVIEW_TIMING=1` 可记录页面创建、DOM 就绪及完整加载耗时。

尚未发送的会话在模型菜单中切换豆包与原生 API 模型时复用同一条本地记录，并尽力双向传递输入框的文字（包括清空）。草稿仅保存在内存，不自动发送；原生附件不上传豆包；往返时文字未改动则保留原生附件，网页修改文字后丢弃原生附件，网页插入的图片一律忽略。豆包进入临时会话路由后即视为已开始，不等待标题生成再锁定会话归属。网页结构或编辑器未就绪时，文字传递可能无法完成。

应用重启时清理从未输入内容、未关联远端会话的豆包 New Chat 占位记录；已输入过内容、手动命名或收藏的记录保留。是否输入过内容仅保存为标记，不额外持久化输入文字。

## 登录与限制

- 登录状态由系统 WebView 的持久化浏览器存储管理，设置页与聊天页共享；不会把 Cookie 或网页凭据复制到 `state.json`。
- 当前多个豆包 Provider 共用同一浏览器登录，不支持同站点多账号隔离。删除或禁用 Provider 不会清除共享登录。
- `--data-dir` 只切换应用设置和会话目录，不隔离浏览器登录。
- 豆包模型、附件及其他网页能力在网页中操作，不使用原生 API 聊天的模型目录、MCP、消息编辑或 Markdown 导出，也不提供本地 LLM Gateway 转发。
- 需要能访问豆包网页的网络环境。区域限制、登录验证和网页自身的可用性仍由豆包决定；此集成不绕过这些检查。
- 网页结构变化可能影响侧栏隐藏、会话创建识别或标题同步。无法确认新会话归属时不会导入历史会话。
